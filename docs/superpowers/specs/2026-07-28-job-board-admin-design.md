# 채용정보 게시판 (관리자 큐레이션형) 설계 문서

- 작성일: 2026-07-28
- 작성자: hyun (kimch4577@gmail.com)

## 개요

취업정보 사이트. 관리자가 채용공고 PDF를 업로드하면 OpenAI API로 정보를 자동 추출하고,
관리자가 검토·수정 후 게시한다. 일반 이용자는 로그인 후 게시된 채용공고를 검색·조회한다.

이번 스펙은 **관리자 큐레이션 기반의 단순 게시판**이며, 외부 채용 사이트 크롤링, AI 맞춤 추천,
알림, 지원현황 트래커 등은 범위에 포함하지 않는다.

## 범위 (Scope)

### 포함
- 일반 회원가입/로그인 (이메일 + 비밀번호, 세션 기반)
- 관리자 PDF 업로드 → OpenAI API 자동 정보 추출 → 검토/수정 후 등록
- 채용공고 목록 조회 (검색 + 기본 필터), 상세 조회
- 관리자: 채용공고 수정/삭제, 회원 목록에서 관리자 권한 부여/회수
- 지원기간 만료 공고 자동 마감 처리 (스케줄러)

### 제외 (이번 버전에서 다루지 않음)
- URL 등록을 통한 채용정보 수집 (추후 별도 스펙으로 진행 가능)
- SNS(소셜) 로그인
- 외부 채용 사이트 크롤링/API 연동
- AI 맞춤 추천, 알림, 지원현황 트래커
- 클라우드 배포 (로컬 개발 환경 대상)

## 기술 스택

| 영역 | 기술 |
|---|---|
| Frontend | React (SPA, React Router) |
| Backend | Spring Boot (REST API) |
| 인증 | Spring Session 기반 세션 인증 |
| DB | H2 (파일 모드 — 재시작 후에도 데이터 유지) |
| PDF 텍스트 추출 | Apache PDFBox |
| 정보 자동 추출 | OpenAI API (GPT) |
| 파일 저장 | 서버 로컬 파일시스템 (`uploads/` 디렉토리) |
| 실행 환경 | 로컬 개발 전용 (별도 클라우드 배포 없음) |

흐름: `React (localhost:3000)` → `Spring Boot REST API (localhost:8080)` → `H2` / `OpenAI API`

## 데이터 모델

### User (회원)

| 필드 | 설명 |
|---|---|
| id | PK |
| email | 로그인 ID (unique) |
| password | BCrypt 암호화 저장 |
| name | 이름 |
| role | `USER` \| `ADMIN` |
| createdAt | 가입일 |

- 최초 관리자 1명은 초기 데이터(seed)로 생성한다.
- 이후 관리자는 회원 목록 화면에서 다른 회원에게 `ADMIN` 권한을 부여/회수할 수 있다.

### JobPosting (채용공고)

| 필드 | 설명 |
|---|---|
| id | PK |
| companyName | 회사명 |
| location | 회사 위치 |
| careerLevel | 경력 (신입/경력/무관 등, 구조화된 값) |
| education | 학력 (학력무관/고졸/대졸 등, 구조화된 값) |
| employmentType | 고용형태 (정규직/계약직/인턴 등, 구조화된 값) |
| conditionNote | 채용조건 자유텍스트 비고 |
| applyStartDate | 지원 시작일 |
| applyEndDate | 지원 종료일 |
| applyMethod | 지원방법 (PDF 원문 텍스트 그대로 저장, 사이트 내 자체 지원 기능 없음) |
| salaryMin | 예상급여 최소값 (숫자, 만원 단위) |
| salaryMax | 예상급여 최대값 (숫자, 만원 단위) |
| salaryNote | 급여 비고 (예: "회사 내규에 따름") |
| pdfFilePath | 원본 PDF 서버 저장 경로 |
| status | `ACTIVE` \| `CLOSED` |
| createdBy | 등록한 관리자 (User FK) |
| createdAt / updatedAt | 생성/수정일시 |

## 주요 기능 흐름

### 일반 이용자
1. 이메일/비밀번호로 회원가입 후 로그인 (세션 생성)
2. 로그인 상태에서만 채용공고 목록·상세 조회 가능 — 비로그인 접근 시 로그인 페이지로 리다이렉트
3. 목록에서 키워드 검색 + 기본 필터(지역, 고용형태 등) 사용
4. 상세 페이지에서 회사명, 위치, 채용조건, 지원기간, 지원방법, 예상급여 등 전체 정보 확인

### 관리자
1. PDF 업로드 → 서버가 Apache PDFBox로 텍스트 추출 → OpenAI API 호출로 회사명·위치·채용조건·지원기간·지원방법·예상급여 등 구조화 정보 추출 (**동기 처리**: 업로드 요청에 대한 응답으로 바로 추출 결과 반환)
2. 추출된 내용이 미리 채워진 검토/수정 폼을 관리자에게 제공
3. 관리자가 내용을 확인·수정 후 저장 → DB에 채용공고 등록, 원본 PDF는 서버 로컬 파일시스템에 보관
4. 관리자 페이지에서 등록된 공고 목록 조회/수정/삭제
5. 회원 목록 화면에서 특정 회원에게 `ADMIN` 권한 부여/회수

### 자동 마감 처리
- 매일 정해진 시각(예: 자정)에 스케줄러가 `applyEndDate`가 지난 `ACTIVE` 공고를 `CLOSED`로 변경
- `CLOSED` 공고는 삭제하지 않고 데이터는 보존하되, 일반 목록에서는 숨김

## 에러 처리

- **PDF 파싱 실패** (텍스트 추출 불가, OpenAI API 오류/시간초과): 오류 메시지를 표시하고 빈 검토 폼을 제공해 수동 입력으로 폴백 (등록 프로세스 자체가 막히지 않도록 함)
- **PDF가 아닌 파일 업로드**: 업로드 단계에서 확장자/MIME 타입 검증 후 거부
- **권한 없는 접근**: 일반 회원의 관리자 페이지 접근 시 403, 비로그인 사용자는 로그인 페이지로 리다이렉트
- **로그인 실패**: 이메일/비밀번호 불일치 시 에러 메시지 표시

## 테스트 전략

- **백엔드**: 서비스 레이어 단위 테스트(JUnit) + 리포지토리/컨트롤러 통합 테스트 (H2 기반, `@SpringBootTest`)
- **프론트엔드**: 핵심 플로우(로그인, 목록 조회, 관리자 등록 폼) 위주 컴포넌트 테스트 — 전체 커버리지보다 핵심 경로 우선

## 결정 사항 요약 (브레인스토밍 중 확정된 항목)

- 프론트엔드/백엔드: React + Spring Boot
- DB: H2 (파일 모드)
- 인증: 세션 기반, 이메일/비밀번호 회원가입만 (SNS 로그인 없음)
- 관리자 구분: 일반 회원가입 + 권한 부여 방식, 최초 관리자는 seed로 생성
- URL 등록 기능은 이번 버전에서 제외 (PDF 업로드만 지원)
- PDF 파싱 API: OpenAI API (GPT)
- PDF 처리 방식: 동기 처리
- 원본 PDF 저장 위치: 서버 로컬 파일시스템
- 지원방법: 자체 지원 기능 없이 PDF 원문 텍스트 표시
- 예상급여: 최소~최대 숫자 범위 + 비고 텍스트
- 마감 처리: 자동 마감 + 목록에서 숨김
- 실행 환경: 로컬 개발 전용
